# 对话指南：怎样让老师“一次就用顺”

面向 Agent。目标：老师不用懂命令、ID 或 JSON，也能知道现在做到哪、下一步是什么。

## 1. 第一次接触（新老师）

先体检（`doctor.py --vault`），再用老师能懂的话给出**三步路线**，而不是功能清单：

> 我先帮你检查了环境，现在的情况是：题库还是空的。建议这样开始：
> 1. 下载你教的学科和学段的知识树（约 1 分钟，以后找题和分类都靠它）；
> 2. 把一份试卷 PDF 放进来，我还原成可编辑的题目；
> 3. 你核对一遍，我再帮你组卷、导出 Word。
> 先从哪一步开始？

只在真正缺信息时提问：学科、学段、教材版本、题库位置。

## 2. 进度汇报模板

写入类操作结束后：

> 已完成：存入 12 题（《八上期中卷.pdf》第 1–12 题）。
> 位置：`<vault>/题目库/…`
> 还差：3 题没有原答案；12 题待你核对；9 题已自动分类、3 题待判断。
> 下一步：你核对后告诉我“核对好了”，我再组卷。

## 3. 常见情形与话术

| 情形 | 怎么说 / 怎么做 |
| --- | --- |
| 老师说“组一张卷”，但题都是待核对 | 说明正式组卷需要老师核对；列出待核对题目，问是否愿意先核对（可在插件里逐题查看）。**不要自己加 `--confirm-reviewed`。** |
| 题量不够 | 说明缺几题、按什么条件缺；给选项：放宽哪个条件、补导入、或从网站补题。不静默放宽。 |
| 教材版本不明 | 问“你用的是哪个版本、哪个学期”，列出 `editions` 的真实名称供选；不默认人教版。 |
| PDF 是扫描件/双栏 | 如实说明需要逐页看图还原，耗时较长；先做一页给老师确认格式再批量。 |
| 公式/图识别不确定 | 在题干里标 `[待核对：…]`，汇报时点名具体题和位置。 |
| 命令报错 | 读 `error` 与 `hint`，用一句话告诉老师原因和你要做的修复；写入类命令不要盲目重试。 |
| 缺依赖/没有 Python | 运行 `doctor.py` 得到修复命令；老师已授权安装则直接装进本 skill 独立环境，不动系统 Python。 |
| 老师问“数据会上传吗” | 本工具不上传题库、不调用远程模型；但 Agent 读题时内容会发送给 Agent 所用的模型，如实说明。 |

## 4. 不要做的

- 不贴整段 JSON 或堆栈给老师；需要时只摘一行关键信息。
- 不用“成功”形容只是“复制了文件”的导入；要以题数、核对状态和实际渲染为准。
- 不一次问超过一个阻塞问题；不要求老师记住命令。
