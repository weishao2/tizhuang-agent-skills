# 教师工作台与目录

`organize` 将旧中文布局升级为 `teacher/v2`。先在仓库旁生成完整 ZIP 备份，再整理；发生错误自动还原文件。只在老师选定的题库运行。不要把任意资料目录当成题库整理。

| 日常入口 | 用途 |
| --- | --- |
| 题库首页.md / 插件首页 | 总题量、待核对、待分类、最近保存、导入进度和试卷 |
| 题目库 | 一题一份笔记，按学科学段与主分类存放 |
| 待整理 | PDF 导入报告与尚未完成的输入 |
| 试卷 | 无答案打印稿、教师稿及冻结快照 |
| 教学笔记 | 老师自己的讲法和备课记录 |
| 资料 | 原 PDF、附件、教材和知识目录、旧导航；不是日常选题入口 |

维护索引和导入过程放在隐藏的 `.bank`。原题目 ID、正文区块和来源记录保持稳定。未命名 `.base` 只有内容确认为默认空表视图才归档；自定义视图和老师其他文件不自动删除。

题目按一个主分类存放。工作台的教材树、知识树和标签提供多维关系，同一道题不复制。`knowledge_tree_ids`、`knowledge_ids` 和教材章节 ID 保持各自含义；网站考点名称只有在同一学科学段的标准树中唯一精确匹配才关联。知识点重名或缺失时保留待分类，不能做相似名称的强行映射。

文件名清除图片 Markdown 与网址，带图题目用“图 · ”提示；工作台列表用 `[图]`，展开后才显示完整题目。不能改动题干本身的图片引用。

原生 Obsidian 标签写到 `tags`。兼容旧笔记的 `标签`，但当 `tags` 存在时以它为准，包括空数组，避免老师删除标签后旧字段又恢复。标签层级用 `/`，检索父标签包含子标签。插件“分类 / 标签”可修改知识关联和标签，先备份原笔记，保留题干、答案和老师批注。

刷新首页：

```text
<python> <cli> --vault <vault> dashboard
```

首页和分类界面读取本地 Markdown 与目录快照，不发起收费请求。插件保存的网站题进入同一题目库；旧 `question-bank` skill 只是可选题源，任何本地工作流都不要求安装它。

## Agent 自动知识点分类

知识点标签只是文字，`knowledge_tree_ids` 才是知识点树中的归属。PDF 入库和老师要求自动分类时，阅读题目正文、配图及已存在的答案，从该题学科学段的本地标准知识树中选择真实节点。一道综合题可多选；根据考查内容关联节点，不因题干里出现某个词就强行归类。优先合适的具体节点；找不到时选择确实适用的上级节点并说明原因，不虚构节点，不混入竞赛或其他学段。未确定的题保留待分类并说明具体缺口。标签和知识点可以同时保留。

新 PDF 在 v2 分题清单内填写 `knowledge_tree_ids`，工具由目录中的明确映射生成 `knowledge_ids` 和标准考点标签。导入后验证每题节点，而不是只统计 tags。已有题使用 `classify` 批量补分类，禁止重新导入同 ID 题目或改写正文来更新分类。

```json
{
  "schema": "tizhuang.classification/v1",
  "items": [{
    "id": "existing-question-id",
    "knowledge_tree_ids": ["confirmed-node-id"],
    "expected_content_sha256": "sha256-of-content-newline-answer-newline-analysis",
    "reason": "结合题干说明所选知识点的依据"
  }]
}
```

哈希输入是当前规范化记录的 `content + "\n" + answer + "\n" + analysis` 的 UTF-8 字节。通过 `search` 或 `read_note` 读取实际记录，不能凭空填写。

```text
<python> <cli> --vault <vault> classify --file <checked-plan.json> --plan
<python> <cli> --vault <vault> classify --file <checked-plan.json>
```

先验证整批节点、学科学段及内容哈希，再备份并写入。追加所选节点及其明确关联的精确知识编号，保留老师已有分类与标签；正文、答案、分值、教材、审核状态、文件路径、其他属性和老师批注保持不变。生成知识点链接，并更新首页与可重建索引。相同清单重复应用不重复添加；内容变化要求重新判断。备份、依据与结果存于 `.bank/classification/`。这些是 Agent 的分类判断，老师可以在插件“分类 / 标签”调整，不意味着题目已经核对。

在插件“我的题目 → 分类方式 → 知识点”中查看树，父节点包含所有子节点的题目，同题不会因多个考点重复计数。原笔记不自动移动，避免破坏已有链接；通过知识点树与首页即可多维浏览。

章节必须另行确认教材版本与真实章节目录。用户选择仅分知识点时，保持 `edition_id`、`chapter_ids` 原样；不要用试卷地区、年份或知识点名称猜教材。当前 classify 命令只负责知识点，不声称已经完成章节自动归类。


## 插件按钮与批处理

插件“我的题目 → 自动分类”会调用 `auto-classify`：只处理没有知识节点的题，精确匹配已有考点标签与当前学科学段知识树的唯一同名节点。它不包含语义模型；不因正文出现关键词就归类，不替换已经关联的知识点。缺失知识树、重名或没有可靠标签的题生成报告，按钮可复制 Agent 续办指令。Agent 接到该指令后应实际阅读题目与配图，按上文的 classify 协议完成语义判断。

```text
<python> <cli> --vault <vault> auto-classify
<python> <cli> --vault <vault> auto-classify --batch <PDF批次>
<python> <cli> --vault <vault> auto-classify --ids <题目ID> <题目ID>
<python> <cli> --vault <vault> repair-papers
```

PDF commit 成功后会自动运行该批次匹配；Agent 应在分题清单中直接提供核实的知识点，减少人工续办。分类失败不撤销已存题目，JSON 的 classification.error 会明确说明需要继续处理。不要把“已复制 Agent 指令”描述成已完成分类。

`repair-papers` 修复已知的旧打印稿相对链接，增加插件直接打开 Word/HTML 的按钮；只备份收起历史打印稿目录中符合旧命名规则且确认为 0 字节的 `.md` 空文件，保留有内容的笔记及所有 HTML。备份在 `.bank/paper-repair`。不使用 Obsidian 打开不存在的 HTML 笔记。
